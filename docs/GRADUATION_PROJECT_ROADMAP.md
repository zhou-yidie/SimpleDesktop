# SimpleDesktop 技术方案与中长期路线图

## 1. 技术方案详述

### 1.1 核心架构设计：插件化驱动的 MVVM 分层架构
本项目摒弃了传统的单体 Android 应用架构，采用自研的模块化插件系统结合 Jetpack 最新技术栈，实现了高内聚、低耦合的系统级设计。

*   **1.1.1 表现层 (UI Layer - Jetpack Compose)**：
    *   全面采用声明式 UI 框架 Compose 构建所有界面。相比传统的 XML 布局，Compose 的数据驱动特性极大地简化了适老化所需的动态 UI 调整。
    *   全局封装了 `SimpleDesktopTheme`，通过 `LocalComposition` 下发字体缩放比例（FontSize）和高对比度模式（ContrastMode），实现了秒级的全局主题无缝热切换。
*   **1.1.2 逻辑控制层 (Domain Layer - ViewModel)**：
    *   遵循单一职责原则，`ViewModel` 通过 `StateFlow` 和 `SharedFlow` 暴露不变的 UI 状态（State）和一次性事件（Event）。
    *   利用 Kotlin 协程（Coroutines）处理所有异步任务，避免主线程阻塞导致的 UI 掉帧（Jank），确保了即使在性能较弱的老年机上也能保持 60fps 的流畅体验。
*   **1.1.3 数据持久层 (Data Layer - Repository)**：
    *   采用 **Repository Pattern（存储库模式）**，对 ViewModel 屏蔽底层数据来源。
    *   **强类型键值存储**：使用 Jetpack `DataStore Preferences` 替代 `SharedPreferences`，基于 Protobuf 的序列化机制和完全的异步流（Flow）支持，彻底解决了跨进程/多线程写入时的 ANR 隐患。
    *   **关系型数据引擎**：使用 `Room` 数据库存储复杂的联系人与应用列表数据，利用预编译 SQL 和自动生成的 DAO 层，并建立多字段联合索引，确保拖拽排序和实时搜索的高效执行。
*   **1.1.4 依赖注入中心 (DI Layer - Hilt)**：
    *   引入 Google 官方的 `Dagger-Hilt` 框架进行依赖注入。统一管理 `Repository`、`Network Client` 和系统 `Service` 的单例生命周期，大幅减少了样板代码，并为后续的单元测试（Mocking）铺平了道路。

### 1.2 关键技术与亮点模块深度剖析

#### 1.2.1 自研微内核插件系统 (Micro-kernel Plugin System)
为了彻底解耦越来越复杂的桌面功能，系统设计了一套自研的插件化管理框架：
*   **核心契约**：定义了严格的 `IPlugin` 接口协议，强制规范了模块的 `initialize`、`start`、`stop`、`destroy` 生命周期。
*   **依赖图拓扑排序**：`PluginManager` 内部实现了针对插件间依赖关系的自动拓扑排序算法，以此推导出的启动顺序图保证了被依赖模块永远优先完成初始化，避免了启动期的 Crash。
*   **隔离与动态性**：通过将“应用管理”、“联系人管理”与“天气模块”彻底抽离为插件，主系统（Host）退化为一个纯粹的插件调度与 UI 容器，为未来横向扩展（如“健康监测插件”）打下了极其优良的生态基础。

#### 1.2.2 基于无障碍服务的第三方应用控制（微信直联技术）
**业务痛点**：微信作为极其封闭的系统，不提供任何 API 供第三方应用直接唤起视频或语音通话，而这一步骤对老年人而言学习成本极高。
*   **技术突破**：深度定制 Android `AccessibilityService` (无障碍服务)。
*   **智能节点定位算法**：针对微信版本频繁更新导致控件 ID 混淆（Obfuscation）的问题，系统放弃了脆弱的硬编码 ID 匹配，转而采用以“内容描述（ContentDescription）”和“控件类型与层级特征（Node Hierarchy Heuristics）”相结合的多维匹配寻址算法。
*   **自动化状态机**：在后台建立隐式的自动化状态机，接管屏幕流转：“唤醒微信 -> 精准搜索好友 -> 进入聊天窗 -> 触发底部面板 -> 寻找并点击音视频通话节点”。以毫秒级的时间间隔模拟手势，对用户实现了完全的“一键无感直达”。

#### 1.2.3 基于前台服务的心跳网络守护机制
**业务痛点**：老年人经常误触关闭系统 WiFi 或开启飞行模式，导致与家人失联。
*   **实时流控监听**：`WifiMonitorService` 作为长驻前台服务（Foreground Service），绑定系统级 Notification 以最高优先级保活。通过 `ConnectivityManager` 注册 `NetworkCallback`，实现了对网络状态的毫秒级感知。
*   **多层级容错倒计时**：摒弃了简单的状态回调，引入了多层级容灾。网络断开时并不是立即干预，而是启动内部维护的 60 秒 `CountDownTimer` 以容忍网络抖动。
*   **高版本 Android 策略突破**：适配 Android 10+ API 限制（无法通过代码强行开启/关闭 WiFi）。巧妙利用唤起系统 `Settings.Panel.ACTION_WIFI` 面板，配合屏幕高亮遮罩与跨进程的 `VoiceAssistant` TTS 语音急促播报，实现了“系统限制防线下的最强手动引导”。

## 2. 发展路线图 (Roadmap)

我们将项目的发展分为近期完善、中期增强、长期生态三个阶段。

### 2.1 短期规划 (1-3 个月)：稳定性与核心优化
*   **UI/UX 打磨**：
    *   引入更多微妙的微动画（Micro-animations），让老年人感知点击反馈。
    *   优化 `Coil` 图片加载缓存，确保在低端设备上滑动联系人列表不卡顿。
*   **语音增强**：
    *   增加“全局语音读屏”功能，用户手指滑动到任何卡片，系统即朗读该卡片功能。
    *   支持简单的离线语音指令（如“打开微信”、“给儿子打电话”）。
*   **权限卫士**：集成更友好的权限请求引导，通过动态图文解释为什么要开启“电话”或“无障碍”权限。

### 2.2 中期规划 (3-9 个月)：智能化与辅助升级 (AI+)
*   **大模型语音助手**：
    *   集成轻量级端侧大模型（如 Gemini Nano）或云端 API，提供“聊天陪伴”功能，缓解独居老人孤独感。
    *   AI 自动摘要未读通知（短信、微信），提取关键信息并朗读，降低老年人阅读门槛。
*   **健康插件包**：
    *   開發并集成“用药提醒”插件，支持拍照识别药盒。
    *   通过蓝牙连接第三方血压计/血糖仪，数据自动同步并在首页醒目显示。
*   **远程辅助协助**：
    *   开发“反向控制”功能，允许子女通过特定安全认证，远程登录协助老人修改桌面配置、清理垃圾或设置提醒。

### 2.3 长期规划 (1 年及以上)：智慧养老生态
*   **智慧养老集成**：
    *   与社区服务系统联动，集成“一键订餐”、“医保查询”等民生接口。
    *   紧急求助 (SOS) 升级：结合地理围栏，一旦老人离开安全区域或检测到跌倒，自动开启紧急摄像头并向子女及社区发送求救报警。
*   **多设备互联**：
    *   适配平板设备（大屏模式）与电视机（大字模式）。
    *   作为智能家居的“入口端”，通过大字界面控制家里的灯光、空调等。
*   **开放平台化**：
    *   完善插件 SDK，允许第三方开发者为该系统开发“适老化”应用插件。
