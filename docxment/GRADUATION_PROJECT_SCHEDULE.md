# SimpleDesktop 毕业设计七周开发详细进度规划

由于本项目是作为毕业设计（毕设）进行，为了方便汇报每周的开发进度、里程碑及关键技术产出，将整个开发过程划分为 7 个自然周的详细计划。

---

## 第一周：需求调研、环境搭建与架构设计

### 1. 核心目标
*   明确针对老年人用户的核心使用痛点（如视力下降导致的看不清文字、记忆力减退导致的找不到应用、社交隔离导致的沟通困难等）。
*   完成 Android 项目的初始化。
*   确定项目的核心技术栈与基础架构。

### 2. 具体任务清单
*   **需求分析与原型**：
    *   梳理核心功能模块：主界面信息板、联系人管理（微信快速拨打）、应用管理、系统设置。
    *   绘制重点页面的交互草图（大字体、大卡片）。
*   **工程构建**：
    *   创建基于 Kotlin 和 Jetpack Compose 的空项目，基于 MVVM 架构搭建项目骨架。
    *   配置并引入依赖库：`Hilt`（依赖注入）、`Room`（本地数据库）、`DataStore`（偏好设置）、`Retrofit/OkHttp`（网络请求）、`Coil`（图片加载）。
*   **底层基建**：
    *   设计 DataStore 的 `SettingsRepository` 层，支持对各类设置项（语音、字体大小、对比度、主题）的全局 Flow 订阅与持久化管理。

### 3. 本周汇报重点/产出
*   **文档**：详细需求分析文档。
*   **代码**：搭建了集成了 Hilt 与 DataStore 的基础脚手架，核心架构的 `View-ViewModel-Repository` 数据流转跑通。

### 4. 教师过程指导记录
*   **指导意见**：本周需求调研充分，抓住了老年人手机使用中的核心痛点（字体小、入口深）。采用 Kotlin + Jetpack Compose 是目前非常前沿的 Android 原生技术栈，MVVM 架构和 Hilt 的引入为后续的复杂状态管理打下了良好基础。建议在设计存储结构时，充分考虑后续联系人、常用应用等数据扩展的可能性，保证 Room 数据库设计的合理性。

---

## 第二周：视觉基础建设与主题定制系统

### 1. 核心目标
*   根据需求分析，构建符合老年人视觉特征的用户体验 (UI/UX) 标准。
*   开发一套完整的主题定制系统。

### 2. 具体任务清单
*   **主题引擎开发**：
    *   利用 Jetpack Compose 的 `MaterialTheme` 特性，定义 `SimpleDesktopTheme`。
    *   实现**蓝色 (Blue)** 和 **橙色 (Orange)** 两套色彩方案。
    *   实现**字体缩放机制** (Small/Medium/Large) 与**高对比度模式** (Normal/High)。
*   **UI 基础组件库封装**：
    *   封装统一的顶部导航条（回退按钮支持大点击区域）。
    *   基于 `Card` 封装圆角大卡片组件，增强立体感和可点击感知。
*   **设置页面骨架开发**：
    *   构建 `SettingsScreen`，提供各项偏好设置的调整开关，完成数据到 UI 的真实双向绑定与实时刷新测试。

### 3. 本周汇报重点/产出
*   **视觉规范**：大字体与高对比度的最终视觉定稿。
*   **功能实现**：全局的主题无缝切换机制，`SettingsScreen` 与底层 DataStore 的完美耦合。

### 4. 教师过程指导记录
*   **指导意见**：UI 视觉规范制定得很详细，特别是针对高对比度和大字体的动态适配，这是适老化设计的核心。在使用 Compose 构建大面积 Card 组件时，建议注意不同屏幕尺寸的适配（包括可能存在的横屏状态）。此外，DataStore 的引入能够有效解决 SharedPreferences 可能会带来的 ANR 问题，这体现了良好的工程实践。建议下一步进行多机型适配的初步测试。

## 第三周：桌面核心框架与应用管理

### 1. 核心目标
*   实现“桌面”（Launcher）最纯粹的基础能力，接管系统主界面并管理本地应用。

### 2. 具体任务清单
*   **桌面系统接管**：
    *   配置 `AndroidManifest.xml` 中的核心 `intent-filter` (如 `android.intent.category.HOME` 和 `android.intent.category.DEFAULT`)。
    *   实现 Home 键、Back 键的按键拦截保护（在桌面模式下屏蔽意外退出）。
*   **应用管理模块开发**：
    *   利用 `PackageManager` 扫描本机已安装且可启动的应用程序，过滤无效应用。
    *   利用 `Room` 数据库存储自定义的“常用应用”列表，建立 `AppInfo` 实体结构。
*   **常用应用 UI 展示**：
    *   实现带大图标的应用九宫格或横排卡片（`AppCard`），使用 Coil 优化应用图标 Bitmap 的解析与渲染性能。
    *   开发交互式拖拽排序功能，以便用户自定义优先使用哪些 App。

### 3. 本周汇报重点/产出
*   **系统级交互**：应用成功作为桌面启动器运行。
*   **功能实现**：高效流畅的本地应用检索、展示与启动功能，以及基于 Room 的常用应用持久化存取。

### 4. 教师过程指导记录
*   **指导意见**：将应用注册为系统级 Launch 模式这步走得很扎实，基本实现了接管系统桌面的预期目标。Room 数据库和 Coil 在“常用应用”展示和图标加载方面的结合应用非常恰当。请务必重点关注 Home 键和 Back 键拦截可能带来的异常死锁问题，确保提供一个“退出桌面模式”的安全出口，以免用户在遇到 Bug 时无法切回原生系统。

## 第四周：信息聚合面板（时间、农历与天气）

### 1. 核心目标
*   开发主屏幕顶部的高密度、高对比度“信息枢纽”，提供对老年人极具价值的日常信息。

### 2. 具体任务清单
*   **时间与日期引擎**：
    *   开发定时器机制（如 `Flow` 结合 `delay`），实现 UI 层面上数字时钟的**秒级无感刷新**。
*   **农历信息集成**：
    *   引入第三方 Lunar 库，在 `DateUtils` 中开发公历转农历算法，输出易读的节气与农历格式。
*   **实时天气模块开发**：
    *   对接外部免费天气 API 接口（利用 Retrofit）。
    *   数据结构 `WeatherInfo` 与服务端 JSON 的映射。
    *   在视图层，开发“天气图标-温度-状态”的映射展示逻辑。

### 3. 本周汇报重点/产出
*   **功能实现**：首页置顶的包含精准时间、农历、以及网络拉取天气的综合信息卡片。

### 4. 教师过程指导记录
*   **指导意见**：信息聚合面板的构思很实用，特别是农历显示，非常符合特定用户群体的习惯。使用 Flow 进行时钟的秒级刷新是一个高效的方案。在处理网络拉取天气数据时，建议考虑弱网环境下的重试策略以及异常处理（如无网络时的默认 UI 占位符）。这会对后续提升应用稳定性有很大帮助。

## 第五周：通信增强与微信无障碍集成

### 1. 核心目标
*   重塑沟通体验，降低老年人与子女拨打电话、使用微信音视频通话的门槛。这也是本项目最具技术挑战的功能之一。

### 2. 具体任务清单
*   **联系人管理系统**：
    *   基于 `Room` 构建本地联系人表，支持字段：姓名、电话、微信昵称、大头像。
    *   开发添加、编辑、删除和拖拽排序功能的界面。
    *   设计主页的网格形联系人卡片展示。
*   **电话权限与直拨**：
    *   集成 `XXPermissions` 处理运行时权限（CALL_PHONE）申请，实现一键直拨。
*   **微信辅助操控 (Accessibility)**：
    *   **难点攻克**：针对微信进行逆向分析，寻找可用的 AccessibilityNodeInfo 节点特征。
    *   开发 `WeChatHelper` 无障碍自动化服务，通过 `performAction` 模拟点击流程（搜索好友 -> 进入聊天 -> 展开面板 -> 点击语音/视频通话）。

### 3. 本周汇报重点/产出
*   **核心功能**：一键微信直连的跑通，大幅简化老人的社交沟通链路。
*   **技术突破**：Android `AccessibilityService` 深度利用与微信控件反混淆识别方案的落实。

### 4. 教师过程指导记录
*   **指导意见**：本周的微信无障碍（Accessibility）自动化功能是整个系统最具技术亮点的部分！成功识别并模拟第三方应用（微信）的控件点击，是对 Android 系统机制的深度挖掘。提醒一点：各个手机厂商（如华为、小米）对 Accessibility 权限的后台限制较严，后续需重点解决“被系统杀后台导致无障碍失效”的问题。

## 第六周：网络守护机制与语音辅助增强

### 1. 核心目标
*   提升系统健壮性，防止老年人因为误操作导致手机长期断网甚至失联。同时加入语音反馈，方便视力不佳的用户。

### 2. 具体任务清单
*   **WiFi 前台监控服务 (`WifiMonitorService`)**：
    *   开发一个长驻的前台 Service (`START_STICKY`)，在通知栏注册 Notification 防止被杀。
    *   使用 `ConnectivityManager.NetworkCallback` 实时监听 WiFi 状态变更。
*   **异常自愈与交互干预**：
    *   网络断开时，启动一个 `CountDownTimer` 触发 60 秒的容忍倒计时。
    *   倒计时结束仍未恢复，向 UI 发送 LocalBroadcast，弹出全屏警告对话框，同时针对高版本 Android 引导用户前往系统 `Settings.Panel.ACTION_WIFI`。
*   **语音反馈助理 (`VoiceAssistant`)**：
    *   封装 Android 原生 `TextToSpeech (TTS)` 服务，提供全局的发音、朗读速度与音量控制。
    *   将 TTS 与重大提示事件（如无WiFi警报、来电等）或特定操作（按钮点击反馈）绑定。

### 3. 本周汇报重点/产出
*   **系统稳定性**：7x24 小时后台网络状态守护与断连弹窗提醒功能。
*   **无障碍优化**：语音 TTS 能力的全局接入。

### 4. 教师过程指导记录
*   **指导意见**：网络守护（WifiMonitorService）和语音播报（VoiceAssistant）功能大幅提升了系统的容错率和健壮性。处理 Android 10+ 无法直接代码干预 WiFi 开关的问题时，使用引导跳转是一个符合规范的选择。在使用前台 Service 保活的同时，建议进一步优化功耗表现，以免因为持续的轮询或守护机制导致老年机原本衰退的电池续航变差。

## 第七周：插件化架构调整与最终收尾优化

### 1. 核心目标
*   对前期快速迭代的代码进行一次系统性重构，提高模块的解耦程度。
*   完成最终的性能优化、Bug 修复和体验打磨，准备毕设答辩。

### 2. 具体任务清单
*   **自研插件化重构**：
    *   **架构设计**：抽象出 `IPlugin`、`IPluginHost`、`IPluginMessenger` 等接口。
    *   **模块剥离**：将“应用管理”、“联系人管理”、“天气模块”分别改造成实现 `IPlugin` 接口的独立组件。
    *   **依赖图解析**：实现 `PluginManager`，利用拓扑排序解决插件间的初始化依赖关系，统一管理它们的启动与销毁。
*   **性能调优与收尾**：
    *   解决 Compose 列表中的过度重组 (Recomposition) 问题，提高滚动流畅度。
    *   调整首页手电筒大图标等交互细节。
    *   撰写、修改并冻结相关技术文档（如 `README.md`，此处的 7 周进度表等），以供毕设论文引用。

### 3. 本周汇报重点/产出
*   **软件工程实践**：高内聚、低耦合的插件架构重构的全面落地。
*   **最终交付物**：符合预期功能指标的 Android Apk，以及完整的技术文档体系。

### 4. 教师过程指导记录
*   **指导意见**：后期的插件化架构重构使得整个项目由单纯的“功能堆砌”跃升为具有一定工程规范的架构体系。重构过程对降低代码耦合度起到了积极作用。目前的系统已经具备了很高的成熟度。接下来的重点应放在毕业论文的写作上，注意将项目中对“无障碍”、“插件化”、“适老化交互”的思考，理论化地落实在论文的章节中。期待你的最终答辩表现！
